# Where the data comes from

Every project document and record the swarm reads is written by [swarm/planning_case.py](swarm/planning_case.py), [swarm/site_case.py](swarm/site_case.py),
[swarm/generator.py](swarm/generator.py) and [swarm/project.py](swarm/project.py). No file, table or figure from a real project, company, person or dataset is
used, and no real data was used to fit or calibrate anything.

The one real source is public: the workforce and material norms in [swarm/norms.py](swarm/norms.py) are copied from the Indonesian national standard **SNI 7394:2008**,
*Tata cara perhitungan harga satuan pekerjaan beton untuk konstruksi bangunan gedung dan perumahan*, and were checked against its tables. Its section 6.10 prints the units
of sand and gravel as m3 beside figures that are kg in every other grade of the table; they are treated as kg.

| What | Source |
|---|---|
| The consultant's planning package: brief, drawings, specification, inspection plan, BoQ, programme, logistics note and rates | Invented, written for this case, with its disagreements planted on purpose |
| Workforce and material per unit of work | SNI 7394:2008 |
| Project, contractor, owner, subcontractor and supplier names | Invented, marked "fictional" |
| Region | A placeholder, "Region 3" |
| BoQ items, quantities and unit prices | Invented round numbers, chosen to look plausible, not taken from any price list |
| Claimed, planned and actual progress | Invented per line, to set up each test scenario |
| Activities, durations and dependencies | Invented |
| Recovery options, rates and damages per day | Invented |
| Contract clauses, specifications, inspection plans, weather forecasts and rosters | Invented documents, written for this case |
| WhatsApp, Slack and Gmail messages | Invented, served by a demo MCP server |
| RFIs, NCRs, inspections and purchase orders | Invented |
| Subcontractor documents, their expiry dates and invoices | Invented |
| Work packages, control budget, commitments and actual cost | Invented, from the shares listed below |
| Daily log entries | Generated from the numbers above plus a few hand-written trap entries, then reworded by `muse-spark-1.3`. Code refused any change to a number, and the wording was read for changes in meaning |
| Site photos | AI-generated by `gpt-image-2` and `muse-image-1.0` from made-up scene descriptions, stamped "SYNTHETIC, AI-GENERATED". `assets/photos_manifest.json` says which model made each one. Image search and web tools were off for Muse Image |
| Change orders | Invented |

## Assumptions we chose

These are design choices, not measured values:

| Assumption | Value | Where |
|---|---|---|
| Differences that count as agreeing | 5 percentage points | `TOLERANCE_PCT` in `swarm/reconcile.py` |
| Evidence too old to show the current state | 21 days before the cut-off | `STALE_DAYS` in `swarm/config.py` |
| Control budget against the BoQ's sell value | 88% | `COST_SHARE` in `swarm/project.py` |
| Share of each budget already committed | 97% | `COMMIT_SHARE` in `swarm/project.py` |
| Actual cost against earned value, by package | 0.97 to 1.08 | `cost_factor` in `PACKAGES`, `swarm/project.py` |
| Retention | 5% | `RETENTION` in `swarm/project.py` |
| Share of verified work already certified, and share claimed this month | 78%, and 18% (34% for the one subcontractor set to bill ahead) | The seeding in `swarm/project.py` |
| Crew the pour needs | 26 | `CREW_NEEDED` in `swarm/project.py` |
| Effective hours in a person-day (OH) | 7 | `HOURS_PER_OH` in `swarm/norms.py` |
| Concrete spillage at the mixer, skip and tremie | 2.5% | `CONCRETE_WASTE_PCT` in `swarm/norms.py` |
| Plywood waste | 4.2%: the standard's 0.35 sheet per m2 against what a 1.22 x 2.44 m sheet covers | `PLYWOOD_NET_PER_M2` in `swarm/norms.py` |
| A quantity that agrees with the BoQ | Within 3% | `TOLERANCE` in `swarm/opc.py` |
| Liquidated damages | Rp 25 million a day | `LD_PER_DAY` in `swarm/site_case.py` |

## How the photo counts were checked

Image models do not reliably draw an exact count, so every accepted photo was counted by eye (by Claude, during the build), and
`swarm/scenes.py` records what the image really shows, not what was asked for. Photos that broke a test scenario were generated
again. A view is treated as representative of its whole BoQ item.

## What the test score means

The score compares a run with the answer planted in the case. It only describes this synthetic project, and it stops being given once the
records change. It says nothing about how the swarm would do on a real project, and a score from the offline mock says nothing about accuracy
at all.
